# Configuration reference

> Generated by `pnpm docs:config` from `src/config/schema.ts` and `src/config/defaults.ts`.
> Do not edit by hand: change the schema (every key has a `.describe()`) or the generator
> (`scripts/gen-config-reference.ts`) and regenerate. `test/unit/docs-config.test.ts` fails when this file is stale.

Dispatch is configured with four kinds of YAML file. Every file starts with `version: 1`, is
validated strictly (an unknown key is an error, not ignored), and an empty file is the same as
`version: 1`. A file with a newer version than this Dispatch supports is refused with a request to
upgrade.

| File | Global location | Repo location | What it holds |
| --- | --- | --- | --- |
| Config | `~/.dispatch/config.yaml` (or `$DISPATCH_HOME/config.yaml`) | `<repo>/.dispatch/config.yaml` | Providers, security limits, active profile and preset, pins, thresholds |
| Profile | `~/.dispatch/profiles/<name>.yaml` | `<repo>/.dispatch/profiles/<name>.yaml` | A named routing strategy: an ordered list of rules |
| Mapping | `~/.dispatch/mappings/<name>.yaml` | `<repo>/.dispatch/mappings/<name>.yaml` | A tier preset (named after the file) and/or model tables |
| Shipped | `assets/profiles`, `assets/mappings`, `assets/models` in the package | | `balance`, `preserve`, `specialize`, `off`; `mirror`, `economy`, `custom`; one model table per adapter |

A broken **global** config stops the command (exit 2). A broken **repo**, profile or mapping file is
skipped and reported as an error by `dispatch validate`; `run` then exits 2 instead of routing with a
policy you did not intend.

## Creating the global config: `dispatch setup`

`dispatch setup` (and `dispatch install` the first time) writes a fully commented
`~/.dispatch/config.yaml` when none exists, after four questions: the client you mainly use
(`main_host`), the plan of each CLI it finds (`providers.<id>.plan`), the starting strategy
(`profile`: balance, preserve or specialize) and the autonomy of delegated agents (`autonomy`,
default `worktree`; `direct` asks for a typed confirmation). It never overwrites an existing
config; `dispatch setup --reconfigure` changes the answers in place and keeps your comments and any
key it does not know. The file is written atomically with mode 0600.

Antigravity is only asked about, probed and written after an explicit opt-in that accepts the
risk and Google's terms (`enabled: true` and `tos_acknowledged: true`).

For scripts and CI, `--non-interactive --yes` takes every answer from flags or a YAML file and
uses the defaults (profile `balance`, autonomy `worktree`, plans unknown, Antigravity off) for the
rest. Without `--yes` it only prints what it would do:

| Flag | Meaning |
| --- | --- |
| `--answers <file>` | YAML with `main_host`, `profile`, `autonomy`, `plans: { claude: max5x }`, `antigravity: { enable: true, accept_terms: true }`; flags win over the file |
| `--host <id>` | `claude-code`, `codex` or `none` |
| `--profile <name>` | `balance`, `preserve`, `specialize` (or any other profile that exists) |
| `--autonomy <level>` | `read-only`, `worktree` or `direct` |
| `--plan <provider>=<plan>` | Repeatable, e.g. `--plan claude=max5x --plan codex=plus`; `unknown` skips the provider |
| `--enable-antigravity --accept-agy-terms` | Both are required to enable Antigravity |
| `--reconfigure` | Change an existing config instead of keeping it |

## Precedence

For ordinary keys the layers are applied in this order, the later one winning:

1. built-in defaults
2. the global config
3. the repo config, only when trusted (see [Trust](#trust))
4. command-line flags (the same keys as the repo config, no `version`)

Profiles and mappings are looked up by name: a file in `~/.dispatch/profiles/` replaces a shipped
profile of the same name, and a trusted repo file replaces both. A mapping file's
`models.<adapter>` block replaces that adapter's whole table.

### Security keys

Security keys (the ones whose **Where** column says "only tighten") cannot be loosened by a repo or by
flags. The global file is yours and may set anything; the effective value is the **most restrictive**
of global, repo and flags:

| Key | Tighter means |
| --- | --- |
| `autonomy`, `providers.<instance>.max_autonomy` | lower: `read-only` < `worktree` < `direct` |
| `allowed_providers` | a subset (the lists are intersected) |
| `concurrency.*`, `providers.<instance>.concurrency`, `max_depth` | a smaller number |
| `network` | `off` rather than `on` |
| `worktree.bootstrap` | `none` rather than `symlink-readonly`; `symlink_paths` a subset; `keep` cannot be turned on |
| `providers.<instance>.enabled` | a repo can disable an instance, never enable one |
| `providers.<instance>.env_passthrough` | a subset |
| `providers.<instance>.binary` | global only |

A looser value is **ignored** and reported as an error (`dispatch validate` lists it and `run` exits
2). A repo can never add a provider instance. Two caps nobody can lift: `antigravity` is always
`read-only`, and an `antigravity` instance on a subscription pool stays disabled until
`tos_acknowledged: true`. The effective ceiling of an instance is the lower of its `max_autonomy` and
the top-level `autonomy`; its concurrency is capped by `concurrency.per_provider`.

### Trust

Repo policy is code: it can change where your tasks go. Dispatch therefore ignores the whole
`.dispatch/` folder of a repository (`config.yaml`, `profiles/*.yaml`, `mappings/*.yaml`) until you run
`dispatch trust` in it (`dispatch install` offers this once).

- The repo identity is the real path of its git common directory, so every linked worktree and every symlinked path of one repo share it.
- `trusted_repos` in the global config stores a sha256 over the relative path and bytes of every policy file, plus one hash per file.
- Any change (an edited, added or removed file) makes the repo untrusted again: the policy is ignored with a warning that names the files, until you review and run `dispatch trust` again.
- A symlink anywhere inside `.dispatch/` makes the repo untrusted, and `dispatch trust` refuses to record it.
- The bytes that were hashed are the bytes that are parsed (each file is read once), so a file swapped in between cannot change what is applied.

## How a task is routed

The router is a pure function of the stored decision input; `dispatch explain` prints the rule chain
it walked and `explain --replay <id>` reproduces any logged decision.

1. **Tier and effort are resolved first**, because rules can match on the tier. A model the host asked for is classified through the `reverse` tables; otherwise the task's own tier; otherwise `unspecified_model`. The active preset then applies `tier_by_task_type` and shifts the effort by `effort_shift` (clamped to `low` < `medium` < `high`).
2. **Layers, in this fixed order; the first match in a layer ends routing:**
   1. `pins` of the config files (whatever the profile)
   2. `mappings.direct`: the first entry whose `from_model` glob (and `from_effort`, if set) matches the model the host asked for; it bypasses tiers
   3. the `rules` of the active `profile`, top to bottom
   4. the tier preset (it only decides tier and effort, as in step 1)
   5. the default: the task stays on the host
3. **Filters apply to every candidate** of a `provider`, `fallback` or `fanout` action: the host itself is never chosen; disabled instances, instances whose autonomy ceiling is below the task's, and instances marked unavailable after a quota hit are dropped; so is an instance below its `hard` threshold. An instance below its `soft` threshold is dropped only when another candidate is not. Unknown quota never blocks a candidate.
4. **Actions:** `provider` (one instance), `host` (stay on the host), `fallback` (try the instances in order or by most remaining quota; the host is always the implicit last step), `fanout` (run on every listed instance, at least two; fewer survivors degrade to one instance or to the host), `reject` (refuse with a reason).

Tiers are `fast`, `balanced`, `max` and efforts `low`, `medium`, `high` in v0.1.

## Config file (`config.yaml`)

The same schema serves the global and the repo file. The **Where** column says which layers may set a key.

| Key | Type | Default | Allowed values | Where | Description |
| --- | --- | --- | --- | --- | --- |
| `version` | number, required |  | `1` | every file | Format version of the file; 1 is the only version. |
| `providers` | map of object |  |  | global; repo and flags only tighten existing instances | Provider instances by id, merged over the built-in claude/codex/antigravity. Keys are instance ids. The built-in instances are `claude`, `codex` and `antigravity`; add more such as `claude-alt` (a second account, see `config_dir`). A repo file can only tighten instances that exist here; it cannot add one. |
| `providers.<instance>.adapter` | string | the instance id |  | global only | Adapter id (claude \| codex \| antigravity); default: the key. Must name a shipped adapter: `claude`, `codex` or `antigravity`. |
| `providers.<instance>.enabled` | boolean | `true` (`antigravity`: `false`) |  | global; repo and flags only tighten | Whether the instance may be used. |
| `providers.<instance>.plan` | string |  |  | global only | Subscription plan, e.g. max, pro, plus. |
| `providers.<instance>.pool` | enum | `subscription` | `subscription` \| `api_credit` \| `unknown` | global only | Billing pool (default subscription). |
| `providers.<instance>.config_dir` | string |  |  | global only | Config dir of this account (e.g. CLAUDE_CONFIG_DIR). For `claude` it becomes `CLAUDE_CONFIG_DIR` of the child (must be absolute, `~/` allowed); for `codex` `CODEX_HOME`. |
| `providers.<instance>.binary` | string |  |  | global only | Explicit CLI binary path. A repo or flag value that differs from the global one is rejected. Without it Dispatch resolves the CLI via PATH and the usual install directories. |
| `providers.<instance>.max_autonomy` | enum | `direct` (`antigravity`: `read-only`) | `read-only` \| `worktree` \| `direct` | global; repo and flags only tighten | Autonomy ceiling of the instance. The effective ceiling is the lower of this and the top-level `autonomy`. `antigravity` is always capped to `read-only`; the claude and codex adapters refuse `direct`. |
| `providers.<instance>.concurrency` | integer | `concurrency.per_provider` | at least 1 | global; repo and flags only tighten | Max concurrent runs. Capped by `concurrency.per_provider`; a repo can only lower it. |
| `providers.<instance>.thresholds` | object |  |  | global only | Quota thresholds of this instance (default soft 20, hard 5). |
| `providers.<instance>.thresholds.soft` | number, required | `20` | 0 to 100 | global only | Below this remaining %, avoid if possible. |
| `providers.<instance>.thresholds.hard` | number, required | `5` | 0 to 100 | global only | Below this remaining %, never use. |
| `providers.<instance>.effort_shift` | integer | `0` |  | global, repo, flags | Effort shift when delegating here. |
| `providers.<instance>.env_passthrough` | list of string | `[]` |  | global; repo and flags only tighten | Extra env vars passed to the child. Names matching host markers, API keys or tokens are dropped even when listed. A repo can only shrink the list. |
| `providers.<instance>.tos_acknowledged` | boolean | `false` |  | global only | antigravity only: required to enable it with a consumer login. Without it a consumer-login `antigravity` stays disabled with a warning. |
| `main_host` | string |  |  | global only | Informational: the client you mainly use as host (claude-code \| codex), recorded by `dispatch setup`; host-independent commands may use it as a default. |
| `autonomy` | enum | `worktree` | `read-only` \| `worktree` \| `direct` | global; repo and flags only tighten | Autonomy ceiling for delegated tasks (read-only &lt; worktree &lt; direct). |
| `allowed_providers` | list of string | every enabled instance |  | global; repo and flags only tighten | Instance ids that may be used; absent = every enabled instance. A repo or flag list can only remove ids (it is intersected with the global one); adding an id is rejected. |
| `concurrency` | object |  |  | global; repo and flags only tighten | Max concurrent runs per instance and overall. |
| `concurrency.per_provider` | integer | `2` | at least 1 | global; repo and flags only tighten | Max concurrent runs on one instance (default 2). |
| `concurrency.total` | integer | `4` | at least 1 | global; repo and flags only tighten | Max concurrent runs across all instances (default 4). |
| `max_depth` | integer | `1` | at least 0 | global; repo and flags only tighten | `run` refuses when DISPATCH_DEPTH &gt;= max_depth (default 1). Delegated children run with `DISPATCH_DEPTH` set, so at the default of 1 a child cannot start another run. |
| `network` | enum | `off` | `off` \| `on` | global; repo and flags only tighten | Network access for children. |
| `worktree` | object |  |  | global; repo and flags only tighten | Worktree sandbox settings. |
| `worktree.bootstrap` | enum | `none` | `none` \| `symlink-readonly` | global; repo and flags only tighten | How dependencies are made available in a worktree. `symlink-readonly` links `symlink_paths` into the worktree read-only; a repo can only choose `none` when the global value is `symlink-readonly`. |
| `worktree.symlink_paths` | list of string | `[]` |  | global; repo and flags only tighten | Paths symlinked read-only by symlink-readonly. A repo list must be a subset of the global one. |
| `worktree.keep` | boolean | `false` |  | global; repo and flags only tighten | Keep worktrees after a run (keep_worktrees). A repo or flag cannot turn this on when it is off. |
| `unspecified_model` | string | `balanced` | `inherit` \| `classify` \| any other non-empty string | global, repo, flags | Tier used when the host names no model: inherit \| classify \| &lt;tier&gt; (default balanced). Valid tiers: `fast`, `balanced`, `max`. `classify` is not implemented in v0.1 and behaves like `balanced`; `inherit` needs an observed host model and otherwise also falls back to `balanced`. |
| `pins` | list of object | `[]` |  | global, repo, flags | Rules evaluated before anything else, whatever the profile. Same rule shape as in a profile; see [Rules](#rules-pins-and-profile-rules). |
| `mappings` | object |  |  | global, repo, flags | Tier preset selection and explicit model mappings. |
| `mappings.preset` | string | `mirror` |  | global, repo, flags | Active tier preset (default mirror). A preset with this name must exist: shipped, global or (trusted) repo. |
| `mappings.direct` | list of object | `[]` |  | global, repo, flags | Explicit model mappings; the first match wins and bypasses tiers. |
| `mappings.direct[].from_model` | string, required |  |  | global, repo, flags | Host model glob, e.g. claude-opus-\*. |
| `mappings.direct[].from_effort` | string |  |  | global, repo, flags | Host effort; absent matches any. |
| `mappings.direct[].instance` | string, required |  |  | global, repo, flags | Target instance id. |
| `mappings.direct[].model` | string, required |  |  | global, repo, flags | Target model. |
| `mappings.direct[].effort` | string, required |  |  | global, repo, flags | Target native effort. |
| `profile` | string | `balance` |  | global, repo, flags | Active routing profile (default balance). A profile with this name must exist: shipped, global or (trusted) repo. |
| `shadow_profiles` | list of string | `[]` |  | global, repo, flags | Profiles evaluated in shadow mode. Profiles must exist. They are evaluated next to the active one (`status --compare`) and never change what runs. |
| `thresholds` | map of object |  |  | global, repo, flags | Per-instance quota thresholds overrides. Keys must be existing instance ids; an unknown id is a warning. Equivalent to `providers.<instance>.thresholds`. |
| `thresholds.<instance>.soft` | number, required | `20` | 0 to 100 | global, repo, flags | Below this remaining %, avoid if possible. |
| `thresholds.<instance>.hard` | number, required | `5` | 0 to 100 | global, repo, flags | Below this remaining %, never use. |
| `timeouts` | object |  |  | global, repo, flags | Run timeouts. |
| `timeouts.default_task_ms` | integer | `600000` | at least 1 | global, repo, flags | Timeout of a delegated task in milliseconds (default 600000). |
| `retention_days` | number | `30` | greater than 0 | global only | How long `dispatch gc` keeps finished runs and their history (default 30). |
| `quota` | object |  |  | global only | Quota reading settings (global file only). |
| `quota.cache_minutes` | number | `5` | at least 0 | global only | Minutes a real quota reading stays fresh (default 5). |
| `quota.readers` | map of object | `{}` |  | global only | Quota readers by reader id (`claude-usage`, `claude-passive`, `codex-app-server`, `agy-usage`) or instance id; `enabled: false` turns a reader off. Routing works with every reader disabled (the estimator takes over). |
| `quota.readers.<instance>.enabled` | boolean |  |  | global only | `false` turns this reader (or every reader of this instance) off. |
| `quota.readers.<instance>.llm_fallback` | boolean |  |  | global only | `claude-usage` only: when `/usage` output cannot be parsed, let Haiku extract the quota lines (only the quota header is sent; only in `status`/`doctor`; default true). |
| `hosts` | object |  |  | global only | Host integration settings (global file only). |
| `hosts.codex` | object |  |  | global only | Codex host integration. |

| `hosts.claude-code` | object |  |  | global only | Claude Code host integration. |
| `hosts.claude-code.hard` | boolean |  |  | global only | Rewrite intercepted Claude Code sub-agent calls (Agent tool) to the `dispatch:dispatch` sub-agent in trusted repos whose policy delegates (default true); false keeps only the SessionStart context. |
| `hosts.claude-code.intercept` | list of string |  |  | global only | Sub-agent types the hard mode redirects (default ["general-purpose"]; a call without a type counts as general-purpose). `"*"` means every type; `dispatch:dispatch` is never redirected. |
| `trusted_repos` | map of object |  |  | global only | Written by `dispatch trust`, keyed by realpath of the git common dir. Do not edit by hand. Not allowed in repo files or flags (they are rejected as unknown keys). |
| `trusted_repos.<repo-id>.hash` | string, required |  |  | global only | sha256 over the relative path and bytes of every policy file. |
| `trusted_repos.<repo-id>.files` | map of string, required |  |  | global only | Repo-relative path → sha256 of each trusted file. |

### Example: global config

```yaml
# ~/.dispatch/config.yaml  (or $DISPATCH_HOME/config.yaml)
version: 1

main_host: claude-code                   # informational: the client you mainly work in

# Provider instances. claude, codex and antigravity exist without being listed; list one to
# describe your account (plan) or to change a setting. Add instances for extra accounts.
providers:
  claude:
    plan: max
  codex:
    plan: plus
    thresholds: { soft: 30, hard: 10 }   # avoid below 30% remaining, never use below 10%
  claude-alt:                            # a second Claude account of the same adapter
    adapter: claude
    config_dir: ~/.claude-alt            # becomes CLAUDE_CONFIG_DIR of the child
    plan: pro
    max_autonomy: read-only              # this account only reviews
  antigravity:                           # experimental, read-only, off by default
    enabled: true
    tos_acknowledged: true               # required for a consumer login (see the README)

# SECURITY keys: you may set anything here; a repo or flag can only tighten them.
autonomy: worktree                       # ceiling: read-only < worktree < direct
concurrency: { per_provider: 2, total: 4 }
max_depth: 1
network: off
worktree: { bootstrap: none, symlink_paths: [], keep: false }

# Ordinary keys: flags > trusted repo > this file > defaults.
profile: balance
unspecified_model: balanced
mappings:
  preset: mirror
timeouts:
  default_task_ms: 600000
shadow_profiles: [preserve]              # evaluated next to the active profile, never executed
quota:
  cache_minutes: 5
  readers:
    codex: { enabled: true }

# Written by `dispatch trust`; do not edit by hand.
# trusted_repos:
#   /home/me/src/app/.git:
#     hash: <sha256>
#     files: { .dispatch/config.yaml: <sha256> }
#     trusted_at: "2026-11-07T09:00:00.000Z"
```

### Example: repo config

```yaml
# <repo>/.dispatch/config.yaml  (committed; applies only after `dispatch trust`)
version: 1

# Ordinary keys override the global file.
profile: preserve
unspecified_model: balanced
pins:                                    # evaluated before anything else, whatever the profile
  - id: migrations-stay-on-host
    description: Never delegate database migrations.
    match: { paths: ["db/migrations/**"] }
    action: { type: host }
mappings:
  preset: economy
  direct:                                # explicit model mappings; the first match wins
    - { from_model: "claude-opus-*", from_effort: high, instance: codex, model: gpt-6.1-sol, effort: high }
thresholds:
  codex: { soft: 40, hard: 15 }
timeouts:
  default_task_ms: 900000

# SECURITY keys: these can only be tightened. A looser value is ignored and reported as an error.
autonomy: worktree
allowed_providers: [codex, claude]
concurrency: { per_provider: 1, total: 2 }
network: off
worktree: { keep: false }
providers:
  codex: { max_autonomy: worktree }      # lower than the global ceiling is fine
```

## Rules: pins and profile rules

A rule is `id` + optional `match` + `action`. All fields present in `match` must hold (logical AND);
an empty or missing `match` matches every task. List-valued fields match when the task's value is one
of the listed values. `id` is what `explain` shows in the rule chain.

| Key | Type | Default | Allowed values | Description |
| --- | --- | --- | --- | --- |
| `id` | string, required |  |  | Rule id, shown in the rule chain of `explain`. |
| `description` | string |  |  | Free text. |
| `match` | object |  |  | Conditions; all present fields must hold. Empty matches every task. |
| `match.task_type` | list of string |  |  | Task types, e.g. [test, docs]. Free-form; the shipped profiles use test, docs, refactor, review, feature and bugfix. |
| `match.paths` | list of string |  |  | Repo-relative globs; any task path matching any glob. |
| `match.tier` | list of string |  |  | Resolved tiers of the task. |
| `match.autonomy` | list of enum |  | items: `read-only` \| `worktree` \| `direct` | Requested autonomy levels. |
| `match.min_remaining_pct` | map of number |  | values: 0 to 100 | Minimum remaining quota (0-100) per instance id; unknown usage never matches. |
| `match.reliability` | list of enum |  | items: `real` \| `estimated` \| `stale` \| `unknown` | Accepted reliabilities of the quota data of the instances in the action. |
| `match.prior_outcome` | list of enum |  | items: `failed` \| `timeout` \| `quota_exhausted` \| `rejected` | Matches when an earlier task of the session had one of these outcomes. |
| `action` | object, required |  | `type`: `provider` \| `host` \| `fallback` \| `fanout` \| `reject` | provider{instance} \| host \| fallback{instances, strategy: ordered\|most_remaining} \| fanout{instances} \| reject{reason}. |
| `action.type` | enum, required |  | `provider` \| `host` \| `fallback` \| `fanout` \| `reject` | What the rule does with a matching task. |
| `action.instance` | string, required |  |  | Used by action type `provider`. Instance id that takes the task. |
| `action.instances` | list of string, required |  |  | Used by action type `fallback`, `fanout`. `fallback` needs at least one instance, `fanout` at least two. For `fanout`, instances that are filtered out are dropped; with fewer than two left it degrades to one instance or the host. |
| `action.strategy` | enum |  | `ordered` \| `most_remaining` | Used by action type `fallback`. `ordered` tries the instances as written; `most_remaining` sorts them by remaining quota first. Default `ordered`. |
| `action.reason` | string, required |  |  | Used by action type `reject`. Why the task is refused; shown to the caller and in `explain`. |

## Profile file (`profiles/<name>.yaml`)

The profile name is the file name without `.yaml`. Activate one with `profile:` in a config file or
`dispatch use <name>`. Shipped: `balance` (default; most remaining quota), `preserve` (the host only
orchestrates), `specialize` (task type picks the provider) and `off` (never delegate). They are plain
YAML in `assets/profiles/`: read and copy them.

| Key | Type | Default | Allowed values | Description |
| --- | --- | --- | --- | --- |
| `version` | number, required |  | `1` | Format version of the file; 1 is the only version. |
| `description` | string |  |  | Free text. |
| `rules` | list of object, required |  |  | Evaluated top to bottom; first match wins. Same rule shape as `pins`; see [Rules](#rules-pins-and-profile-rules). Put a rule without `match` last: it matches every task. |

Each entry of `rules` has the shape described under [Rules](#rules-pins-and-profile-rules).

### Example: profile

```yaml
# <home or repo>/profiles/team-review.yaml  (the profile name is the file name)
version: 1
description: Reviews on two providers, docs on codex, everything else by remaining quota.
rules:                                   # evaluated top to bottom; the first match wins
  - id: never-delegate-secrets
    match: { paths: ["secrets/**"] }
    action: { type: reject, reason: "secrets/ is never delegated" }

  - id: second-opinion                   # runs on both and returns both results
    description: Reviews run on two accounts.
    match: { task_type: [review], autonomy: [read-only] }
    action: { type: fanout, instances: [codex, claude-alt] }

  - id: docs-on-codex
    match: { task_type: [docs, test] }
    action: { type: provider, instance: codex }

  - id: codex-while-plenty
    match:
      min_remaining_pct: { codex: 30 }   # unknown usage never satisfies this
      reliability: [real, estimated]
    action: { type: provider, instance: codex }

  - id: after-a-quota-hit
    match: { prior_outcome: [quota_exhausted] }
    action: { type: host }

  - id: default                          # no match: takes every task, so keep it last
    action: { type: fallback, instances: [claude, codex], strategy: most_remaining }
```

## Mapping file (`mappings/<name>.yaml`)

A mapping file can define a **tier preset** (the preset name is the file name) and/or **model tables**
that replace an adapter's shipped table. Activate a preset with `mappings.preset` in a config file.
Shipped presets: `mirror` (default; same tier and effort everywhere), `economy` (effort -1) and `custom`
(an empty template). The shipped model tables are in `assets/models/<adapter>.yaml`, which use this same
format with only the `models:` block. Explicit `model -> instance:model:effort` mappings are not part of
a mapping file: they are `mappings.direct` in the config file.

| Key | Type | Default | Allowed values | Description |
| --- | --- | --- | --- | --- |
| `version` | number, required |  | `1` | Format version of the file; 1 is the only version. |
| `description` | string |  |  | Free text. |
| `preset` | object |  |  | Tier preset named after the file. |
| `preset.description` | string |  |  | Free text. |
| `preset.effort_shift` | integer |  |  | Effort levels to shift when delegating (negative = cheaper); clamped to the scale. The shift moves along `low` &lt; `medium` &lt; `high` and is clamped at both ends. |
| `preset.tier_by_task_type` | map of string |  |  | Task type → tier override, e.g. { test: fast }. Tiers: `fast`, `balanced`, `max`. |
| `models` | map of object |  |  | Adapter id → model table; replaces that adapter's table. Keys are adapter ids (`claude`, `codex`, `antigravity`). A table replaces the adapter's whole shipped table; copy the shipped one first. |
| `models.<adapter>.tiers` | map of object, required |  |  | Tier → model. |
| `models.<adapter>.tiers.<tier>.model` | string, required |  |  | Native model name. |
| `models.<adapter>.tiers.<tier>.effort` | map of string, required |  |  | Dispatch effort → native effort. Keys are Dispatch efforts (`low`, `medium`, `high`); values are what the CLI is given. |
| `models.<adapter>.tiers.<tier>.relative_cost` | number, required |  | greater than 0 | Indicative cost; 1 = cheapest. |
| `models.<adapter>.reverse` | list of object, required |  |  | Ordered model-glob → tier list used to classify the host's model. Ordered; the first glob that matches the model name the host asked for decides its tier. |
| `models.<adapter>.reverse[].pattern` | string, required |  |  | Glob matched against the model name. |
| `models.<adapter>.reverse[].tier` | string, required |  |  | Tier given to a model that matches. |

### Example: mapping

```yaml
# <home or repo>/mappings/thrifty.yaml  (the preset name is the file name)
version: 1
description: Cheap tests and docs, strongest model for reviews.
preset:
  description: One effort level lower; tests and docs on the fast tier, reviews on max.
  effort_shift: -1
  tier_by_task_type: { test: fast, docs: fast, review: max }

# Optional: replace an adapter's model table (this one replaces the whole codex table).
models:
  codex:
    tiers:
      fast: { model: gpt-6-luna, effort: { low: low, medium: medium, high: high }, relative_cost: 1 }
      balanced: { model: gpt-6-sol, effort: { low: low, medium: medium, high: high }, relative_cost: 3 }
      max: { model: gpt-6.1-sol, effort: { low: medium, medium: high, high: xhigh }, relative_cost: 6 }
    reverse:
      - { pattern: "*luna*", tier: fast }
      - { pattern: "*sol*", tier: max }
```

## Checking your configuration

- `dispatch validate` loads the effective configuration and reports unknown instances, undefined tiers or efforts, models missing from a table, duplicate or contradictory mappings, rules that can never fire (after a catch-all or shadowed by an earlier rule), fanouts without two usable instances, and `soft` below `hard`. It exits 2 on any error.
- `dispatch explain --task "..."` shows which layer and rule decided a task and which candidates were filtered.
- `dispatch trust` (re)trusts the repo policy after you reviewed it.
